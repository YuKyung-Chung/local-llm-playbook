# 실습 2. 코드에서 LLM 호출하기

## 목표

터미널 대화가 아니라 **내 프로그램에서** LLM을 부릅니다. 여기부터가 개발자의 영역입니다.

## 2-1. OpenAI 호환 API가 뭔가

Ollama는 `http://localhost:11434/v1` 에서 **OpenAI와 똑같은 규격의 API**를 제공합니다.

이게 왜 중요하냐면,

```
개발 PC   : openai 라이브러리 -> localhost:11434 (Ollama)
사내 서버 : openai 라이브러리 -> llm.company.local:8000 (vLLM)
```

**코드는 그대로, base_url만 바꾸면 됩니다.** 그래서 지금 Ollama로 배운 게 나중에 그대로 쓰입니다.

`openai` 라이브러리를 쓴다고 해서 OpenAI 회사로 데이터가 가는 게 아닙니다. 그냥 **HTTP 클라이언트 규격**일 뿐입니다. 이건 보안 심의 때 반드시 설명해야 할 포인트입니다. (실제로 오해받기 쉬운 지점입니다)

## 2-2. 첫 호출

`C:\llm-lab\01_first_call.py`

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",  # 로컬 Ollama
    api_key="ollama",                       # 아무 값이나. 로컬은 인증 안 함
)

MODEL = "qwen3:8b"

resp = client.chat.completions.create(
    model=MODEL,
    messages=[
        {"role": "system", "content": "당신은 간결하게 답하는 한국어 도우미입니다."},
        {"role": "user", "content": "RAG가 뭔지 3문장으로 설명해줘."},
    ],
    temperature=0.2,
)

print(resp.choices[0].message.content)
print("---")
print("사용 토큰:", resp.usage)
```

실행:

```powershell
python 01_first_call.py
```

## 2-3. messages 구조 이해하기

이게 LLM API의 핵심입니다. **대화는 역할(role)이 붙은 메시지의 배열**입니다.

```python
messages = [
    {"role": "system",    "content": "너는 사내 규정 안내 도우미다."},   # 지시. 맨 앞 1개
    {"role": "user",      "content": "육아휴직 조건이 뭐야?"},            # 사용자
    {"role": "assistant", "content": "취업규칙 제32조에 따르면..."},      # 모델의 이전 답
    {"role": "user",      "content": "그럼 급여는?"},                     # 이어지는 질문
]
```

**아주 중요한 사실: 모델은 기억을 못 합니다.**

"그럼 급여는?" 이라는 질문만 보내면 모델은 무슨 급여인지 모릅니다.
**매번 이전 대화 전체를 다시 보내야** 합니다. 기억을 관리하는 건 우리 코드입니다.

그래서 이런 일이 생깁니다.

1. 대화가 길어지면 토큰이 계속 늘어나고 느려집니다
2. 컨텍스트 한계에 닿으면 오래된 대화를 잘라내야 합니다
3. 그래서 "대화를 요약해서 압축하기" 같은 기법이 필요해집니다

## 2-4. 대화를 이어가는 챗봇

`C:\llm-lab\02_chat.py`

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
MODEL = "qwen3:8b"

messages = [
    {"role": "system", "content": "당신은 친절한 한국어 도우미입니다. 간결하게 답하세요."}
]

print("대화를 시작합니다. 종료하려면 quit 입력\n")

while True:
    user_input = input("나: ")
    if user_input.strip().lower() in ("quit", "exit", "종료"):
        break

    messages.append({"role": "user", "content": user_input})

    resp = client.chat.completions.create(
        model=MODEL,
        messages=messages,          # 전체 대화를 매번 보냄
        temperature=0.3,
    )
    answer = resp.choices[0].message.content

    messages.append({"role": "assistant", "content": answer})  # 답도 기록에 추가

    print(f"AI: {answer}\n")
    print(f"   [누적 토큰: {resp.usage.total_tokens}]\n")
```

**직접 실험해보세요.**

1. "내 이름은 유경이야" 라고 알려준 뒤 "내 이름이 뭐라고?" 라고 물어보면 기억합니다
2. `messages.append({"role": "assistant", ...})` 줄을 주석 처리하고 다시 해보세요. **기억을 못 합니다**
3. 대화를 10번쯤 이어가며 `누적 토큰` 숫자가 어떻게 늘어나는지 보세요

3번이 특히 중요합니다. **토큰이 대화 길이에 따라 눈덩이처럼 불어나는 걸** 눈으로 봐야 GPU 사이징이 이해됩니다.

## 2-5. 오류 처리와 타임아웃

실무 코드에는 반드시 들어가야 합니다.

```python
from openai import OpenAI, APIConnectionError, APITimeoutError

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama",
    timeout=60.0,      # 초. 로컬 모델은 느릴 수 있으니 넉넉히
    max_retries=2,
)

try:
    resp = client.chat.completions.create(model=MODEL, messages=messages)
except APITimeoutError:
    print("모델 응답이 너무 오래 걸립니다.")
except APIConnectionError:
    print("LLM 서버에 연결할 수 없습니다. Ollama가 떠 있나요?")
```

폐쇄망에서는 **모델 서버가 죽었을 때 서비스 전체가 멈추지 않도록** 이런 처리가 필수입니다. 외부 서비스처럼 알아서 복구해주는 주체가 없으니까요.

## 2-6. 설정을 한 곳에 모으기

앞으로 모든 실습에서 계속 쓸 파일입니다. `C:\llm-lab\config.py`

```python
import os
from openai import OpenAI

# 나중에 사내 서버로 옮길 때 이 부분만 바꾸면 됩니다
LLM_BASE_URL = os.getenv("LLM_BASE_URL", "http://localhost:11434/v1")
LLM_API_KEY  = os.getenv("LLM_API_KEY", "ollama")

CHAT_MODEL  = os.getenv("CHAT_MODEL", "qwen3:8b")
EMBED_MODEL = os.getenv("EMBED_MODEL", "bge-m3")


def get_client() -> OpenAI:
    return OpenAI(base_url=LLM_BASE_URL, api_key=LLM_API_KEY, timeout=120.0)
```

**환경변수로 빼두는 이유가 두 가지입니다.**

1. 개발 PC와 폐쇄망 서버에서 코드 수정 없이 주소만 바꿔 쓸 수 있습니다
2. 보안 심의에서 "외부와 통신할 수 있는 지점이 이 한 곳뿐"임을 보여주기 좋습니다
