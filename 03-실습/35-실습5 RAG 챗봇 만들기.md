# 실습 5. RAG 챗봇 만들기

## 목표

검색 + 생성을 합쳐서 **출처를 표시하는 사내 문서 Q&A**를 완성합니다.
**여기까지 하면 사내 데모가 가능합니다.** 이 볼트에서 가장 중요한 실습입니다.

## 5-1. RAG의 전체 흐름 다시 보기

```
질문
  |
  v
[1] 검색: 벡터 DB에서 관련 청크 k개 찾기
  |
  v
[2] 조립: 시스템 프롬프트 + 찾은 청크 + 질문
  |
  v
[3] 생성: LLM 호출
  |
  v
답변 + 출처
```

코드로는 30줄이면 됩니다. 어려운 건 코드가 아니라 **품질을 올리는 일**입니다.

## 5-2. 최소 동작 버전

`C:\llm-lab\rag.py`

```python
import chromadb
from config import get_client, CHAT_MODEL, EMBED_MODEL

client = get_client()
chroma = chromadb.PersistentClient(path="./vectordb")
collection = chroma.get_collection("company_docs")

SYSTEM_PROMPT = """당신은 사내 규정 안내 도우미입니다.

규칙:
1. 아래 [참고자료]에 있는 내용만 근거로 답하세요.
2. 참고자료에 근거가 없으면 "제공된 자료에서 확인되지 않습니다. 담당 부서에 문의해주세요."라고만 답하세요.
3. 추측하거나 일반적인 법령 지식으로 답하지 마세요.
4. 3~5문장으로 간결하게 답하세요.
5. 답변 마지막 줄에 반드시 "출처: (문서명)" 형식으로 표시하세요.
"""


def retrieve(query: str, k: int = 4):
    qv = client.embeddings.create(model=EMBED_MODEL, input=query).data[0].embedding
    res = collection.query(query_embeddings=[qv], n_results=k)
    return [
        {"text": d, "source": m["source"], "score": 1 - dist}
        for d, m, dist in zip(res["documents"][0], res["metadatas"][0], res["distances"][0])
    ]


def build_context(hits) -> str:
    blocks = []
    for i, h in enumerate(hits, 1):
        blocks.append(f"[자료 {i}] (출처: {h['source']})\n{h['text']}")
    return "\n\n".join(blocks)


def ask(question: str, k: int = 4, min_score: float = 0.3):
    hits = retrieve(question, k)

    # 관련도가 너무 낮으면 아예 모델에 묻지 않는다
    hits = [h for h in hits if h["score"] >= min_score]
    if not hits:
        return "관련된 사내 자료를 찾지 못했습니다. 담당 부서에 문의해주세요.", []

    user_msg = f"[참고자료]\n{build_context(hits)}\n\n[질문]\n{question}"

    resp = client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ],
        temperature=0.1,
    )
    return resp.choices[0].message.content, hits


if __name__ == "__main__":
    while True:
        q = input("\n질문: ").strip()
        if q.lower() in ("quit", "exit", "종료"):
            break

        answer, hits = ask(q)
        print(f"\n{answer}")

        if hits:
            print("\n--- 참고한 자료 ---")
            for h in hits:
                print(f"  [{h['score']:.3f}] {h['source']}: {h['text'][:60]}...")
```

**돌려보세요.**

```
질문: 육아휴직 며칠까지 쓸 수 있어?
-> 최대 1년의 육아휴직을 부여합니다. ... 출처: 취업규칙.txt

질문: 우리 회사 주식 배당은 언제 나와?
-> 제공된 자료에서 확인되지 않습니다. 담당 부서에 문의해주세요.
```

두 번째가 제대로 나오면 성공입니다. **모르는 걸 모른다고 말하는 것**이 이 시스템의 핵심 요건입니다.

## 5-3. 핵심 안전장치: min_score 컷

위 코드에서 가장 중요한 줄입니다.

```python
hits = [h for h in hits if h["score"] >= min_score]
```

벡터 DB는 **아무리 관련 없는 질문이라도 "가장 가까운 것 4개"를 무조건 반환합니다.** 유사도 0.05짜리라도 반환합니다.
그 쓰레기를 모델에게 주면 모델은 그걸로 억지 답을 만듭니다.

그래서 **점수가 낮으면 모델을 부르지도 않는 게** 훨씬 안전합니다.
`min_score` 값은 실제 데이터로 튜닝해야 합니다. 0.3~0.5 사이에서 시작하세요.

> Chroma의 `distances` 는 설정한 거리 방식에 따라 의미가 다릅니다. 코사인 기준일 때 `1 - distance` 가 대략 유사도입니다. **실제 값을 여러 질문으로 찍어보고 컷 기준을 정하세요.** 숫자를 그냥 믿지 말고 직접 확인하는 게 맞습니다.

## 5-4. 대화 이력 처리

실제 챗봇은 후속 질문을 받습니다.

```
사용자: 육아휴직 조건이 뭐야?
AI: (답변)
사용자: 그럼 신청은 언제까지 해야 해?    <- "그럼"이 뭘 가리키는지 검색이 모름
```

두 번째 질문을 그대로 검색하면 "신청 언제까지"만으로는 육아휴직 조항을 못 찾습니다.

**해결책: 질문 재작성 (query rewriting)**

```python
REWRITE_PROMPT = """이전 대화를 참고해서, 마지막 질문을 검색에 쓸 수 있는
독립적인 완전한 질문으로 다시 쓰세요. 다른 말 없이 질문만 출력하세요.

[이전 대화]
{history}

[마지막 질문]
{question}"""


def rewrite_query(history: list[dict], question: str) -> str:
    if not history:
        return question

    hist_text = "\n".join(f"{m['role']}: {m['content'][:200]}" for m in history[-4:])
    resp = client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[{"role": "user",
                   "content": REWRITE_PROMPT.format(history=hist_text, question=question)}],
        temperature=0,
        max_tokens=100,
    )
    return resp.choices[0].message.content.strip()
```

"그럼 신청은 언제까지 해야 해?" → "육아휴직 신청 기한은 언제까지인가요?" 로 바뀝니다. 이제 검색이 됩니다.

**대가:** LLM을 한 번 더 부르니 응답이 느려집니다. 첫 질문이거나 대화 이력이 없으면 건너뛰세요.

## 5-5. 품질을 올리는 순서

RAG 품질이 나쁠 때, 사람들이 보통 모델부터 바꾸려 합니다. **틀렸습니다.**
경험상 개선 효과가 큰 순서는 이렇습니다.

1. **검색이 제대로 되고 있는지 먼저 확인한다** ← 문제의 70%가 여기
   답이 이상하면 먼저 `hits` 를 출력해서 **애초에 맞는 문서를 찾아왔는지** 보세요. 엉뚱한 걸 찾아왔으면 모델 탓이 아닙니다
2. **청킹 전략을 바꾼다** (크기, 조항 단위 분할)
3. **하이브리드 검색을 붙인다** (조항 번호, 상품 코드 대응)
4. **k 값과 min_score를 튜닝한다**
5. **시스템 프롬프트를 다듬는다**
6. **리랭킹을 붙인다** (20개 찾아서 5개로 추리기)
7. **그 다음에야 더 큰 모델을 검토한다**

## 5-6. 리랭킹 (선택)

정확도를 한 단계 올리는 방법입니다. 1차로 넉넉히 찾고, LLM에게 골라달라고 합니다.

```python
def rerank_with_llm(question: str, hits: list, top: int = 3):
    listing = "\n\n".join(f"[{i}] {h['text'][:300]}" for i, h in enumerate(hits))
    prompt = f"""질문에 답하는 데 실제로 도움이 되는 자료 번호만 골라
쉼표로 구분해 출력하세요. 없으면 "없음"이라고 답하세요. 다른 말은 하지 마세요.

[질문] {question}

[자료]
{listing}"""

    resp = client.chat.completions.create(
        model=CHAT_MODEL,
        messages=[{"role": "user", "content": prompt}],
        temperature=0, max_tokens=50,
    )
    raw = resp.choices[0].message.content.strip()
    if "없음" in raw:
        return []

    picked = []
    for tok in raw.replace(" ", "").split(","):
        if tok.isdigit() and int(tok) < len(hits):
            picked.append(hits[int(tok)])
    return picked[:top] or hits[:top]
```

> 전용 리랭커 모델(bge-reranker 등)이 더 빠르고 정확합니다. 폐쇄망에 반입할 모델 목록에 추가로 넣을지 검토하세요.

```python
import gradio as gr
from rag import ask


def chat_fn(message, history):
    answer, hits = ask(message)
    if hits:
        sources = "\n".join(f"- {h['source']} (관련도 {h['score']:.2f})" for h in hits)
        answer += f"\n\n---\n참고 문서:\n{sources}"
    return answer


gr.ChatInterface(
    fn=chat_fn,
    title="사내 규정 안내 도우미",
    description="사내 문서를 근거로 답변합니다. 자료에 없는 내용은 답하지 않습니다.",
).launch(server_name="127.0.0.1", server_port=7860)
```

브라우저에서 `http://127.0.0.1:7860`.

> **폐쇄망 주의:** Gradio는 실행할 때 외부 리소스를 받아오려는 경우가 있습니다. 폐쇄망에서는 오프라인 모드 설정이 필요하거나, 아예 FastAPI + 정적 HTML로 직접 만드는 게 확실합니다. 시연용으로만 쓰고 운영 UI는 사내 표준 프레임워크로 만드는 걸 권합니다.

## 5-8. 로그 남기기 (금융권 필수)

```python
import json, datetime, hashlib
from pathlib import Path

LOG_PATH = Path("logs/qa.jsonl")
LOG_PATH.parent.mkdir(exist_ok=True)


def log_qa(user_id: str, question: str, answer: str, hits: list, latency_ms: int):
    record = {
        "ts": datetime.datetime.now().isoformat(),
        "user": hashlib.sha256(user_id.encode()).hexdigest()[:16],  # 가명처리
        "question": question,
        "answer": answer,
        "sources": [h["source"] for h in hits],
        "top_score": hits[0]["score"] if hits else None,
        "latency_ms": latency_ms,
        "model": CHAT_MODEL,
    }
    with LOG_PATH.open("a", encoding="utf-8") as f:
        f.write(json.dumps(record, ensure_ascii=False) + "\n")
```

**남겨야 하는 이유:**

1. 감사 대응 (누가 무엇을 물었고 무엇을 근거로 답했는가)
2. 품질 개선 (검색 실패한 질문들이 개선 목록이 됩니다)
3. 사고 조사 (잘못된 답이 나갔을 때 원인 추적)

`top_score` 를 남기는 게 특히 유용합니다. **점수가 낮은 질문들만 모아보면 어떤 문서가 부족한지** 바로 보입니다.

사용자 ID는 가명처리(해시)하되, 필요 시 역추적이 가능해야 하는지는 사내 정책에 따릅니다. [[43-금융권 보안 규제 고려사항]]
