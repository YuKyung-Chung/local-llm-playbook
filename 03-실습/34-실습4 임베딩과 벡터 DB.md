## 4-2. 임베딩이 뭔지 눈으로 보기

`C:\llm-lab\06_embedding.py`

```python
from config import get_client, EMBED_MODEL

client = get_client()


def embed(text: str) -> list[float]:
    resp = client.embeddings.create(model=EMBED_MODEL, input=text)
    return resp.data[0].embedding


def cosine(a: list[float], b: list[float]) -> float:
    dot = sum(x * y for x, y in zip(a, b))
    na = sum(x * x for x in a) ** 0.5
    nb = sum(y * y for y in b) ** 0.5
    return dot / (na * nb)


v = embed("육아휴직 신청 방법")
print("차원 수:", len(v))
print("앞 5개 값:", v[:5])
print()

base = "육아휴직 신청 방법"
candidates = [
    "출산휴가는 어떻게 신청하나요?",
    "육아기 근로시간 단축 제도",
    "이번 달 원달러 환율 전망",
    "법인카드 사용 규정",
]

bv = embed(base)
for c in candidates:
    print(f"{cosine(bv, embed(c)):.4f}  {c}")
```

**출력을 보세요.**

```
0.78  출산휴가는 어떻게 신청하나요?      <- 글자는 다른데 점수가 높음
0.71  육아기 근로시간 단축 제도
0.31  이번 달 원달러 환율 전망           <- 관계없으니 낮음
0.35  법인카드 사용 규정
```

**"육아휴직"과 "출산휴가"는 겹치는 글자가 없는데도 점수가 높습니다.** 키워드 검색으로는 절대 못 하는 일입니다. 이게 임베딩의 힘이고, RAG가 작동하는 이유입니다.

## 4-3. 문서 쪼개기 (청킹)

문서 전체를 통으로 넣으면 안 됩니다. 이유가 두 가지입니다.

1. 컨텍스트 윈도우를 넘깁니다
2. 100페이지 문서 하나의 벡터는 "이 문서는 전반적으로 인사 관련"이라는 뭉뚱그린 의미밖에 못 담습니다

그래서 **의미 단위로 잘라야** 합니다.

`C:\llm-lab\chunker.py`

```python
def chunk_text(text: str, size: int = 800, overlap: int = 150) -> list[str]:
    """문자 기준으로 자르되 앞뒤를 겹치게 한다."""
    text = text.replace("\r\n", "\n")
    chunks = []
    start = 0
    while start < len(text):
        end = start + size
        chunk = text[start:end]

        # 문장 중간에서 끊기지 않도록 마지막 문장 끝에서 자르기
        if end < len(text):
            for mark in ("\n\n", ".\n", ". ", "다.", "?\n", "!\n"):
                idx = chunk.rfind(mark)
                if idx > size * 0.5:
                    chunk = chunk[: idx + len(mark)]
                    end = start + idx + len(mark)
                    break

        chunk = chunk.strip()
        if chunk:
            chunks.append(chunk)
        start = end - overlap      # 겹치게 이동
        if start <= 0:
            break
    return chunks
```

**겹치기(overlap)를 하는 이유:** 중요한 문장이 정확히 경계에 걸려 잘리면 어느 청크에도 온전히 안 들어갑니다. 앞뒤를 조금씩 겹쳐두면 이 사고를 막습니다.

**크기를 정하는 감각:**

| 청크 크기 | 장점 | 단점 |
|---|---|---|
| 300~500자 | 검색 정확도 높음 | 맥락 부족. 답이 파편적 |
| 800~1200자 | **대체로 좋은 균형** | |
| 2000자 이상 | 맥락 풍부 | 관련 없는 내용이 섞임 |

금융권 규정 문서는 **조항 단위로 자르는 게 가장 좋습니다.** "제32조" 같은 패턴으로 나누면 검색 품질이 확 올라갑니다.

```python
import re

def chunk_by_article(text: str) -> list[str]:
    """제N조 단위로 자르기. 규정 문서에 효과적."""
    parts = re.split(r"(?=제\s*\d+\s*조)", text)
    return [p.strip() for p in parts if p.strip()]
```

## 4-4. 문서 읽어오기

`C:\llm-lab\loader.py`

```python
from pathlib import Path
from pypdf import PdfReader
import docx


def load_file(path: Path) -> str:
    suffix = path.suffix.lower()

    if suffix == ".pdf":
        reader = PdfReader(str(path))
        return "\n".join((page.extract_text() or "") for page in reader.pages)

    if suffix == ".docx":
        d = docx.Document(str(path))
        return "\n".join(p.text for p in d.paragraphs)

    if suffix in (".txt", ".md"):
        return path.read_text(encoding="utf-8")

    raise ValueError(f"지원하지 않는 형식: {suffix}")


def load_dir(folder: str) -> list[tuple[str, str]]:
    """(파일명, 본문) 목록을 반환"""
    out = []
    for p in Path(folder).rglob("*"):
        if p.suffix.lower() in (".pdf", ".docx", ".txt", ".md"):
            try:
                out.append((p.name, load_file(p)))
                print(f"[읽음] {p.name}")
            except Exception as e:
                print(f"[실패] {p.name}: {e}")
    return out
```

> **현실 경고:** 사내 PDF는 스캔본인 경우가 많습니다. 스캔 PDF는 텍스트가 아니라 이미지라서 `extract_text()` 가 빈 문자열을 뱉습니다. 그때는 OCR이 별도로 필요하고, 이건 프로젝트 공수를 크게 늘립니다. **착수 전에 대상 문서가 텍스트 PDF인지 스캔본인지 반드시 확인하세요.** 표가 많은 문서도 텍스트 추출이 깨집니다.

## 4-5. 벡터 DB에 넣기

`C:\llm-lab\build_index.py`

```python
import chromadb
from config import get_client, EMBED_MODEL
from loader import load_dir
from chunker import chunk_text

client = get_client()
chroma = chromadb.PersistentClient(path="./vectordb")   # 파일로 저장됨

collection = chroma.get_or_create_collection(
    name="company_docs",
    metadata={"hnsw:space": "cosine"},      # 코사인 유사도 사용
)


def embed_batch(texts: list[str]) -> list[list[float]]:
    resp = client.embeddings.create(model=EMBED_MODEL, input=texts)
    return [d.embedding for d in resp.data]


def main():
    docs = load_dir("./documents")
    total = 0

    for filename, content in docs:
        chunks = chunk_text(content, size=800, overlap=150)
        if not chunks:
            continue

        # 임베딩은 배치로 처리해야 빠릅니다
        vectors = embed_batch(chunks)

        collection.add(
            ids=[f"{filename}::{i}" for i in range(len(chunks))],
            documents=chunks,
            embeddings=vectors,
            metadatas=[
                {"source": filename, "chunk_index": i}    # 출처 표시에 필수
                for i in range(len(chunks))
            ],
        )
        total += len(chunks)
        print(f"  {filename}: {len(chunks)}개 청크")

    print(f"\n완료. 총 {total}개 청크, 컬렉션 크기 {collection.count()}")


if __name__ == "__main__":
    main()
```

**`metadatas` 에 `source` 를 반드시 넣으세요.** 나중에 "출처: 취업규칙.pdf" 를 표시하려면 이게 있어야 합니다. 금융권에서 출처 없는 답변은 쓸 수 없습니다.

## 4-6. 검색해보기

`C:\llm-lab\search.py`

```python
import chromadb
from config import get_client, EMBED_MODEL

client = get_client()
chroma = chromadb.PersistentClient(path="./vectordb")
collection = chroma.get_collection("company_docs")


def search(query: str, k: int = 3):
    qv = client.embeddings.create(model=EMBED_MODEL, input=query).data[0].embedding
    res = collection.query(query_embeddings=[qv], n_results=k)

    hits = []
    for doc, meta, dist in zip(res["documents"][0], res["metadatas"][0], res["distances"][0]):
        hits.append({"text": doc, "source": meta["source"], "score": 1 - dist})
    return hits


if __name__ == "__main__":
    for q in ["애 키우려고 쉬고 싶은데 어떻게 해요?", "카드 쓰고 나서 뭐 내야 하죠?"]:
        print(f"\n질문: {q}")
        for h in search(q):
            print(f"  [{h['score']:.3f}] {h['source']}")
            print(f"    {h['text'][:80]}...")
```

**주목할 점:** "애 키우려고 쉬고 싶은데" 라는 구어체 질문으로 "제32조 육아휴직"이 검색됩니다. 겹치는 단어가 하나도 없는데도요. **이게 RAG가 실제 사용자 질문에 대응할 수 있는 이유입니다.**

## 4-7. 검색이 안 될 때 (하이브리드 검색)

의미 검색이 약한 경우가 있습니다.

- "제32조 알려줘" → 조항 번호는 의미가 없어서 못 찾음
- "KB-2024-017" 같은 사내 코드 → 마찬가지

**금융권 문서에는 이런 게 널려 있습니다.** 그래서 키워드 검색을 병행합니다.

```python
def hybrid_search(query: str, k: int = 5):
    # 1) 의미 검색
    vector_hits = search(query, k=k * 2)

    # 2) 키워드 검색 (간단 버전: 부분 문자열 포함)
    all_docs = collection.get()
    keyword_hits = [
        {"text": d, "source": m["source"], "score": 0.5}
        for d, m in zip(all_docs["documents"], all_docs["metadatas"])
        if query.strip() in d
    ]

    # 3) 합치고 중복 제거
    seen, merged = set(), []
    for h in keyword_hits + vector_hits:      # 키워드 정확 일치를 우선
        key = h["text"][:50]
        if key not in seen:
            seen.add(key)
            merged.append(h)
    return merged[:k]
```

> 실제 운영에서는 BM25 알고리즘이나 Elasticsearch, 또는 pgvector + PostgreSQL 전문검색을 씁니다. 위 코드는 원리 이해용입니다. 문서가 수만 건이 되면 저 방식은 못 씁니다.
