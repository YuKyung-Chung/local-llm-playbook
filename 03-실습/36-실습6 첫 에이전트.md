# 실습 6. 첫 에이전트 (툴 콜링)

## 목표

모델이 **도구를 골라 쓰는** 루프를 직접 구현합니다.
프레임워크(LangChain 등) 없이 맨손으로 만들어서, 에이전트가 사실 별거 아니라는 걸 확인합니다.

## 6-1. 에이전트의 정체

에이전트를 "스스로 생각하는 AI"라고 설명하는 글이 많은데, 실제로는 **while 루프 하나**입니다.

```
1. 모델에게 묻는다 (사용 가능한 도구 목록도 같이 알려줌)
2. 모델이 최종 답변을 주면 -> 끝
3. 모델이 "이 도구를 이 인자로 불러줘"라고 하면
   -> 우리 코드가 실제로 실행
   -> 결과를 대화에 추가
   -> 1번으로 돌아감
```

**핵심: 실제로 함수를 호출하는 건 모델이 아니라 우리 코드입니다.**
모델은 "이걸 부르면 될 것 같은데?"라고 JSON으로 제안만 합니다.

이 사실이 보안 심의에서 결정적입니다. 권한 검사, 감사 로그, 실행 여부 판단이 전부 **우리 코드 안에서** 이루어집니다. 모델에게 직접 DB 접근 권한을 주는 게 아닙니다.

## 6-2. 도구 정의하기

`C:\llm-lab\tools.py`

```python
import datetime

# --- 실제 동작하는 함수들 ---

def get_today() -> str:
    return datetime.date.today().isoformat()


def calculate(expression: str) -> str:
    """모델은 계산을 못하므로 도구로 뺀다."""
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "오류: 허용되지 않은 문자가 포함되어 있습니다."
    try:
        return str(eval(expression, {"__builtins__": {}}, {}))
    except Exception as e:
        return f"계산 오류: {e}"


# 사내 시스템 연동 자리 (지금은 가짜 데이터)
_LEAVE_DB = {
    "20240101": {"name": "정유경", "remaining": 12.5, "used": 2.5},
    "20200315": {"name": "김철수", "remaining": 3.0, "used": 12.0},
}


def get_leave_balance(employee_id: str) -> str:
    row = _LEAVE_DB.get(employee_id)
    if not row:
        return f"사번 {employee_id}를 찾을 수 없습니다."
    return f"{row['name']}님의 잔여 연차는 {row['remaining']}일입니다. (사용 {row['used']}일)"


# --- 모델에게 알려줄 명세 ---

TOOL_SPECS = [
    {
        "type": "function",
        "function": {
            "name": "get_today",
            "description": "오늘 날짜를 YYYY-MM-DD 형식으로 반환합니다.",
            "parameters": {"type": "object", "properties": {}},
        },
    },
    {
        "type": "function",
        "function": {
            "name": "calculate",
            "description": "사칙연산 수식을 계산합니다. 숫자 계산이 필요할 때 반드시 사용하세요.",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "예: (1200000 * 0.033)"}
                },
                "required": ["expression"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_leave_balance",
            "description": "사번으로 직원의 잔여 연차를 조회합니다.",
            "parameters": {
                "type": "object",
                "properties": {
                    "employee_id": {"type": "string", "description": "8자리 사번. 예: 20240101"}
                },
                "required": ["employee_id"],
            },
        },
    },
]

TOOL_IMPL = {
    "get_today": get_today,
    "calculate": calculate,
    "get_leave_balance": get_leave_balance,
}
```

**description을 성의 있게 쓰세요.** 모델이 도구를 고르는 유일한 근거입니다. 여기가 부실하면 엉뚱한 도구를 부릅니다. 사실상 **프롬프트 엔지니어링**입니다.

## 6-3. 에이전트 루프

`C:\llm-lab\agent.py`

```python
import json
from config import get_client, CHAT_MODEL
from tools import TOOL_SPECS, TOOL_IMPL

client = get_client()

SYSTEM = """당신은 사내 업무 도우미입니다.
숫자 계산과 사내 데이터 조회는 반드시 제공된 도구를 사용하세요. 직접 추측하지 마세요.
도구 결과를 근거로 한국어로 간결하게 답하세요."""


def run_agent(question: str, max_turns: int = 5, verbose: bool = True):
    messages = [
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": question},
    ]

    for turn in range(max_turns):
        resp = client.chat.completions.create(
            model=CHAT_MODEL,
            messages=messages,
            tools=TOOL_SPECS,       # 도구 목록을 알려줌
            temperature=0,
        )
        msg = resp.choices[0].message

        # 도구 호출이 없으면 최종 답변
        if not msg.tool_calls:
            return msg.content

        messages.append(msg)        # 모델의 도구 호출 요청을 대화에 추가

        for call in msg.tool_calls:
            name = call.function.name
            args = json.loads(call.function.arguments or "{}")

            if verbose:
                print(f"  [도구 호출] {name}({args})")

            fn = TOOL_IMPL.get(name)
            if fn is None:
                result = f"오류: 알 수 없는 도구 {name}"
            else:
                try:
                    result = fn(**args)
                except Exception as e:
                    result = f"실행 오류: {e}"

            if verbose:
                print(f"  [결과] {result}")

            messages.append({
                "role": "tool",
                "tool_call_id": call.id,
                "content": str(result),
            })

    return "처리 단계가 너무 많아 중단했습니다."


if __name__ == "__main__":
    for q in [
        "사번 20240101의 잔여 연차가 며칠이야?",
        "월급 320만원의 3.3%는 얼마야?",
        "오늘 며칠이지?",
    ]:
        print(f"\n질문: {q}")
        print(f"답변: {run_agent(q)}")
```

실행하면 이런 게 보입니다.

```
질문: 사번 20240101의 잔여 연차가 며칠이야?
  [도구 호출] get_leave_balance({'employee_id': '20240101'})
  [결과] 정유경님의 잔여 연차는 12.5일입니다. (사용 2.5일)
답변: 정유경님의 잔여 연차는 12.5일입니다.
```

**이게 에이전트의 전부입니다.** 프레임워크들이 하는 일도 결국 이 루프에 편의 기능을 얹은 겁니다.

## 6-4. 반드시 넣어야 할 안전장치

실습 코드에는 최소한만 넣었지만, 실서비스에는 아래가 필수입니다.

### 1) 최대 반복 횟수 제한

```python
for turn in range(max_turns):   # 이미 넣었음
```
없으면 모델이 도구를 무한히 부르며 돌 수 있습니다. **비용과 장애로 직결됩니다.**

### 2) 권한 검사

**모델이 아니라 우리 코드가 합니다.**

```python
def get_leave_balance(employee_id: str, *, requester_id: str) -> str:
    if employee_id != requester_id and not is_hr_manager(requester_id):
        return "권한이 없습니다. 본인의 정보만 조회할 수 있습니다."
    ...
```

**이게 금융권에서 가장 중요한 부분입니다.** 모델은 "사번 아무거나 넣어서 조회해줘"라는 요청에 순순히 응할 수 있습니다. 막는 건 코드입니다.

### 3) 쓰기 작업은 사람 확인을 거친다

```python
WRITE_TOOLS = {"approve_leave", "send_email", "update_record"}

if name in WRITE_TOOLS:
    if not user_confirmed(name, args):
        result = "사용자가 승인하지 않아 실행하지 않았습니다."
```

**1단계에서는 아예 읽기 전용 도구만 노출하는 걸 강력히 권합니다.** 조회만 되는 에이전트도 충분히 유용하고, 심의 통과도 훨씬 쉽습니다.

### 4) 도구 호출 전량 로깅

누가, 언제, 어떤 도구를, 어떤 인자로 불렀고, 결과가 무엇이었는지 전부 남깁니다. 감사 대응의 기본입니다.

### 5) 입력 검증

모델이 만든 인자를 그대로 믿지 마세요. **모델 출력은 외부 입력과 같은 등급으로 다룹니다.**

```python
if not re.fullmatch(r"\d{8}", employee_id):
    return "잘못된 사번 형식입니다."
```

위 `calculate` 함수에서 문자를 화이트리스트로 검사한 것도 같은 이유입니다. (참고로 `eval` 은 실무에서 쓰지 마세요. 여기서는 예제 단순화를 위해 제한을 걸고 쓴 겁니다)

## 6-5. RAG와 에이전트 합치기

RAG 검색 자체를 도구로 만들면 됩니다.

```python
from rag import retrieve, build_context

def search_company_docs(query: str) -> str:
    hits = retrieve(query, k=3)
    if not hits:
        return "관련 문서를 찾지 못했습니다."
    return build_context(hits)

TOOL_SPECS.append({
    "type": "function",
    "function": {
        "name": "search_company_docs",
        "description": "사내 규정, 취업규칙, 업무 매뉴얼을 검색합니다. 사내 제도나 절차에 대한 질문이면 반드시 사용하세요.",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string", "description": "검색할 내용"}},
            "required": ["query"],
        },
    },
})
TOOL_IMPL["search_company_docs"] = search_company_docs
```

이제 모델이 **질문에 따라 알아서 판단합니다.**

- "육아휴직 조건이 뭐야?" → 문서 검색 도구
- "내 잔여 연차는?" → 인사 조회 도구
- "육아휴직 쓰면 내 연차는 어떻게 돼?" → **둘 다 호출**

세 번째 같은 복합 질문을 처리할 수 있다는 게 에이전트를 쓰는 이유입니다.

## 6-6. 작은 모델의 한계

8B 이하 모델은 툴 콜링이 불안정할 수 있습니다. 증상은 이렇습니다.

- 도구를 안 쓰고 그냥 지어냄
- 인자를 엉뚱하게 채움
- JSON 형식이 깨짐

**대응 방법:**

1. 시스템 프롬프트에 "반드시 도구를 사용하라"를 강하게 명시
2. 도구 개수를 줄인다 (10개 넘어가면 급격히 나빠집니다)
3. description을 더 명확하게
4. 툴 콜링을 잘 지원한다고 명시된 모델을 고른다
5. 그래도 안 되면 모델 크기를 올린다

**모델 선정 시 "툴 콜링 지원 여부"를 반드시 체크리스트에 넣으세요.** [[23-모델 크기와 양자화]]
