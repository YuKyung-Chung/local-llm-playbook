# 실습 7. MCP 서버 만들기

## 목표

[[36-실습6 첫 에이전트|실습 6]]에서 만든 도구들을 **MCP 표준 규격**으로 감쌉니다.

## 7-1. MCP를 왜 쓰나

실습 6 방식의 문제는 **도구가 애플리케이션 코드에 박혀 있다**는 겁니다.

같은 사내 인사 조회 기능을 챗봇에서도, 개발자 IDE에서도, 다른 팀 시스템에서도 쓰려면 매번 다시 짜야 합니다.

MCP는 이걸 **USB 규격처럼** 표준화합니다.

```
[MCP 서버: 인사 시스템]  ─┐
[MCP 서버: 문서 검색]    ─┼─>  어떤 MCP 클라이언트든 꽂아 쓸 수 있음
[MCP 서버: 코드 저장소]  ─┘     (사내 챗봇 / IDE / 운영 도구)
```

**폐쇄망에서 특히 유리한 점:**

1. 도구 서버를 **팀별로 따로 운영**할 수 있습니다. 인사팀 MCP 서버는 인사팀이 관리
2. 권한과 감사 로그를 **서버 단위로** 걸 수 있습니다
3. 프로토콜이 로컬 프로세스(stdio)나 사내 HTTP로 돌아서 외부 통신이 필요 없습니다

## 7-2. MCP 구조

| 구성 요소 | 역할 |
|---|---|
| **서버 (Server)** | 도구와 데이터를 제공. 우리가 만드는 것 |
| **클라이언트 (Client)** | 서버에 접속해 도구 목록을 받고 실행을 요청. 챗봇 앱 쪽 |
| **호스트 (Host)** | 클라이언트를 품고 LLM과 연결하는 애플리케이션 |

서버가 제공하는 것은 세 종류입니다.

- **Tools:** 모델이 호출할 수 있는 함수 (조회, 계산, 실행)
- **Resources:** 모델이 읽을 수 있는 데이터 (파일, 문서)
- **Prompts:** 재사용 가능한 프롬프트 템플릿

**실무에서는 Tools가 90%입니다.** 나머지는 나중에 봐도 됩니다.

## 7-4. 첫 MCP 서버

`C:\llm-lab\mcp_hr_server.py`

```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("사내 인사 시스템")

_LEAVE_DB = {
    "20240101": {"name": "정유경", "dept": "IT개발팀", "remaining": 12.5, "used": 2.5},
    "20200315": {"name": "김철수", "dept": "리스크관리팀", "remaining": 3.0, "used": 12.0},
}


@mcp.tool()
def get_leave_balance(employee_id: str) -> str:
    """사번으로 직원의 잔여 연차를 조회합니다.

    Args:
        employee_id: 8자리 사번 (예: 20240101)
    """
    if not employee_id.isdigit() or len(employee_id) != 8:
        return "오류: 사번은 8자리 숫자여야 합니다."

    row = _LEAVE_DB.get(employee_id)
    if not row:
        return f"사번 {employee_id}를 찾을 수 없습니다."

    return (f"{row['name']}({row['dept']})님의 잔여 연차는 "
            f"{row['remaining']}일입니다. 올해 {row['used']}일 사용했습니다.")


@mcp.tool()
def search_employee(name: str) -> str:
    """이름으로 직원을 검색해 사번과 부서를 반환합니다."""
    found = [f"{v['name']} / 사번 {k} / {v['dept']}"
             for k, v in _LEAVE_DB.items() if name in v["name"]]
    return "\n".join(found) if found else f"'{name}' 검색 결과가 없습니다."


if __name__ == "__main__":
    mcp.run()      # 기본 stdio 방식
```

**주목할 점:**

- `@mcp.tool()` 데코레이터만 붙이면 끝입니다
- **함수의 docstring이 곧 모델에게 보여줄 description입니다.** 성의 있게 쓰세요
- **타입 힌트(`employee_id: str`)에서 파라미터 스키마가 자동 생성됩니다.** 실습 6에서 손으로 쓰던 JSON 스키마를 안 써도 됩니다

이게 MCP의 개발 생산성 이점입니다.

## 7-6. 문서 검색 MCP 서버

RAG를 MCP 서버로 감싸는 게 실무에서 훨씬 유용합니다.

`C:\llm-lab\mcp_docs_server.py`

```python
import chromadb
from mcp.server.fastmcp import FastMCP
from config import get_client, EMBED_MODEL

mcp = FastMCP("사내 문서 검색")

_client = get_client()
_chroma = chromadb.PersistentClient(path="./vectordb")
_collection = _chroma.get_collection("company_docs")


@mcp.tool()
def search_documents(query: str, top_k: int = 3) -> str:
    """사내 규정, 취업규칙, 업무 매뉴얼을 검색합니다.
    사내 제도나 절차에 관한 질문이면 반드시 이 도구를 사용하세요.

    Args:
        query: 검색할 내용 (자연어)
        top_k: 반환할 문서 개수 (기본 3, 최대 5)
    """
    top_k = max(1, min(top_k, 5))

    qv = _client.embeddings.create(model=EMBED_MODEL, input=query).data[0].embedding
    res = _collection.query(query_embeddings=[qv], n_results=top_k)

    if not res["documents"][0]:
        return "관련 문서를 찾지 못했습니다."

    blocks = []
    for doc, meta, dist in zip(res["documents"][0], res["metadatas"][0], res["distances"][0]):
        score = 1 - dist
        if score < 0.3:          # 관련도 낮은 건 아예 반환하지 않음
            continue
        blocks.append(f"[출처: {meta['source']} / 관련도 {score:.2f}]\n{doc}")

    return "\n\n".join(blocks) if blocks else "충분히 관련된 문서를 찾지 못했습니다."


@mcp.tool()
def list_documents() -> str:
    """검색 가능한 사내 문서 목록을 반환합니다."""
    all_docs = _collection.get(include=["metadatas"])
    sources = sorted({m["source"] for m in all_docs["metadatas"]})
    return "검색 가능한 문서:\n" + "\n".join(f"- {s}" for s in sources)


if __name__ == "__main__":
    mcp.run()
```

`list_documents` 같은 도구를 넣어두면 사용자가 **"뭘 물어볼 수 있는지" 알 수 있어서** 만족도가 올라갑니다.

## 7-7. 감사 로그와 권한 (금융권 필수)

MCP 서버는 사내 시스템에 닿는 지점이라 여기서 통제해야 합니다.

```python
import json, datetime, functools
from pathlib import Path

AUDIT = Path("logs/mcp_audit.jsonl")
AUDIT.parent.mkdir(exist_ok=True)


def audited(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        started = datetime.datetime.now()
        try:
            result = fn(*args, **kwargs)
            ok, err = True, None
        except Exception as e:
            result, ok, err = None, False, str(e)

        with AUDIT.open("a", encoding="utf-8") as f:
            f.write(json.dumps({
                "ts": started.isoformat(),
                "tool": fn.__name__,
                "args": kwargs,
                "success": ok,
                "error": err,
                "elapsed_ms": int((datetime.datetime.now() - started).total_seconds() * 1000),
            }, ensure_ascii=False) + "\n")

        if not ok:
            raise RuntimeError(err)
        return result
    return wrapper


@mcp.tool()
@audited
def get_leave_balance(employee_id: str) -> str:
    """..."""
```

**권한 처리 원칙:**

1. **읽기 전용 도구부터 시작합니다.** 쓰기 도구는 별도 심의
2. **호출자 신원을 서버가 알아야 합니다.** stdio 방식은 서버를 사용자 세션별로 띄우고, HTTP 방식은 인증 헤더를 씁니다
3. **도구 자체에 권한 검사를 넣습니다.** 클라이언트를 믿지 않습니다
4. **민감 정보는 마스킹해서 반환합니다.** 주민번호, 계좌번호 등이 모델 컨텍스트에 그대로 들어가지 않도록

## 7-8. 클라이언트 없이 서버 검증하기

폐쇄망에서 `mcp dev` 를 못 쓸 때 씁니다.

`C:\llm-lab\test_mcp_server.py`

```python
import asyncio
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client


async def main():
    params = StdioServerParameters(command="python", args=["mcp_hr_server.py"])

    async with stdio_client(params) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            tools = await session.list_tools()
            print("=== 사용 가능한 도구 ===")
            for t in tools.tools:
                print(f"- {t.name}: {t.description}")

            print("\n=== 실행 테스트 ===")
            result = await session.call_tool("get_leave_balance",
                                             {"employee_id": "20240101"})
            print(result.content[0].text)


asyncio.run(main())
```

이 스크립트가 **MCP 클라이언트의 최소 형태**이기도 합니다. 다음 실습에서 이걸 LLM과 연결합니다.
