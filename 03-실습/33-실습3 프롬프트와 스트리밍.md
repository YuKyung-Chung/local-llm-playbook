## 3-1. 스트리밍

`C:\llm-lab\03_stream.py`

```python
from config import get_client, CHAT_MODEL

client = get_client()

stream = client.chat.completions.create(
    model=CHAT_MODEL,
    messages=[{"role": "user", "content": "금융권에서 로컬 LLM을 쓰는 이유를 5가지 알려줘."}],
    temperature=0.3,
    stream=True,          # 이 한 줄
)

for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta:
        print(delta, end="", flush=True)
print()
```

`stream=True` 를 빼고 한 번, 넣고 한 번 돌려보세요.
**총 소요 시간은 같은데 체감은 완전히 다릅니다.** 사내 챗봇에서는 반드시 켜세요.

> 주의: 스트리밍을 쓰면 `resp.usage` 로 토큰 수를 바로 못 받습니다. 필요하면 `stream_options={"include_usage": True}` 를 주거나 별도로 세야 합니다. (서버가 지원해야 합니다)

## 3-2. 시스템 프롬프트의 위력

같은 질문에 시스템 프롬프트만 바꿔서 실행해보세요.

`C:\llm-lab\04_system_prompt.py`

```python
from config import get_client, CHAT_MODEL

client = get_client()
QUESTION = "우리 회사 육아휴직은 며칠인가요?"

SYSTEMS = {
    "없음": "",
    "일반": "당신은 친절한 도우미입니다.",
    "엄격": (
        "당신은 사내 규정 안내 도우미입니다.\n"
        "제공된 [참고자료]에 근거가 없으면 반드시 "
        "'제공된 자료에서 확인되지 않습니다. 인사팀에 문의해주세요.' 라고만 답하세요.\n"
        "추측하거나 일반적인 법 기준을 안내하지 마세요."
    ),
}

for name, sys_prompt in SYSTEMS.items():
    msgs = []
    if sys_prompt:
        msgs.append({"role": "system", "content": sys_prompt})
    msgs.append({"role": "user", "content": QUESTION})

    resp = client.chat.completions.create(model=CHAT_MODEL, messages=msgs, temperature=0)
    print(f"=== [{name}] ===")
    print(resp.choices[0].message.content)
    print()
```

**결과를 비교하세요.**

- "없음"과 "일반"은 근로기준법 일반 내용을 그럴듯하게 답할 겁니다. 우리 회사 규정이 아닌데도요
- "엄격"은 모른다고 답할 확률이 높습니다

**이게 금융권 사내 챗봇의 생명선입니다.** 모르면 모른다고 말하게 만들기.
다만 100%는 아닙니다. 작은 모델일수록 지시를 어깁니다. 그래서 실제 준수율을 [[44-평가와 모니터링]] 에서 측정해야 합니다.

## 3-3. 프롬프트 작성 원칙 5가지

실무에서 효과가 확인된 것만 추렸습니다.

**1. 역할과 범위를 먼저 못 박는다**

> 당신은 사내 규정 안내 도우미다. 규정과 무관한 질문에는 답하지 않는다.

**2. 금지사항을 명시한다**

> 추측하지 마라. 자료에 없는 내용을 만들지 마라. 법률 자문을 하지 마라.

**3. 출력 형식을 지정한다**

> 3~5문장으로 답하고, 마지막 줄에 `출처: 문서명 조항` 형식으로 표시하라.

**4. 예시를 한두 개 넣는다 (few-shot)**

말로 설명하는 것보다 예시 하나가 훨씬 강력합니다.

```
[예시]
질문: 연차는 며칠인가요?
답변: 취업규칙 제25조에 따라 1년 근속 시 15일이 부여됩니다.
출처: 취업규칙 제25조
```

**5. 중요한 지시는 맨 앞과 맨 뒤에 둔다**

모델은 프롬프트 한가운데 있는 내용을 잘 놓칩니다. (lost in the middle 현상)

## 3-4. JSON으로 받기

챗봇이 아니라 **시스템 연동**을 하려면 정해진 구조로 받아야 합니다.

`C:\llm-lab\05_json_out.py`

```python
import json
from config import get_client, CHAT_MODEL

client = get_client()

SYSTEM = """사용자의 문의를 분류하세요. 반드시 아래 JSON 형식으로만 답하고 다른 말은 하지 마세요.

{"category": "인사|전산|회계|기타", "urgency": "높음|보통|낮음", "summary": "한 문장 요약"}"""

USER = "법인카드 결제가 계속 승인 거절되는데 내일 출장이라 급합니다."

resp = client.chat.completions.create(
    model=CHAT_MODEL,
    messages=[
        {"role": "system", "content": SYSTEM},
        {"role": "user", "content": USER},
    ],
    temperature=0,
    response_format={"type": "json_object"},   # JSON 강제 (지원하는 서버에서만)
)

raw = resp.choices[0].message.content
print("원문:", raw)

data = json.loads(raw)
print("분류:", data["category"], "/ 긴급도:", data["urgency"])
```

**실무 주의사항 두 가지.**

1. `response_format` 을 지원하지 않는 모델이나 서버도 있습니다. 그때는 프롬프트로만 유도하고 파싱 실패에 대비해야 합니다
2. 모델이 코드펜스(백틱 세 개)로 감싸서 줄 때가 있습니다. 방어 코드가 필요합니다

```python
def parse_json_safe(text: str):
    text = text.strip()
    if text.startswith("```"):
        parts = text.split("```")
        text = parts[1] if len(parts) > 1 else text
        if text.lstrip().startswith("json"):
            text = text.lstrip()[4:]
    try:
        return json.loads(text.strip())
    except json.JSONDecodeError:
        return None    # 실패하면 재시도하거나 기본값 처리
```

**이 방어 코드는 실무에서 반드시 필요합니다. LLM 출력은 신뢰할 수 없는 외부 입력으로 다루세요.**
사용자 입력을 검증하듯 모델 출력도 검증해야 합니다. 이건 보안 관점에서도 맞는 태도입니다.

## 3-5. 추론(thinking) 모드 주의

최신 모델 중에는 답하기 전에 사고 과정을 `<think>...</think>` 로 먼저 출력하는 것들이 있습니다. (Qwen3 계열 등)
사용자에게 그대로 보여주면 안 되고, JSON 파싱할 때도 걸립니다.

- 모델에 따라 프롬프트나 옵션으로 끌 수 있습니다
- 또는 응답에서 해당 블록을 제거하고 씁니다

```python
import re

def strip_think(text: str) -> str:
    return re.sub(r"<think>.*?</think>", "", text, flags=re.DOTALL).strip()
```
