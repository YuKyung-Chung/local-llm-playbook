# LLM은 어떻게 답을 만드나

## 한 문장 요약

**LLM은 지금까지의 글을 보고 다음 토큰 하나를 확률로 고르는 일을 계속 반복하는 기계입니다.**

## 자동완성의 괴물 버전

핸드폰 키보드의 자동완성을 떠올려 보세요. "오늘 저녁에" 까지 치면 "만나요", "뭐해" 같은 걸 추천해줍니다.
LLM은 그것과 **원리가 같습니다.** 다만 규모가 다릅니다.

- 핸드폰: 최근 몇 단어와 내 사용 이력만 봄
- LLM: 앞선 수만 단어를 전부 보고, 인터넷 규모의 글에서 배운 패턴으로 판단

규모가 어느 선을 넘으니 문법, 상식, 코드 작성, 논리 전개 같은 능력이 **부수적으로 따라 나왔습니다.** 이걸 창발(emergence)이라고 부릅니다.

## 실제 처리 순서

질문을 던졌을 때 안에서 벌어지는 일입니다.

```
1) 토큰화
   "육아휴직 조건 알려줘"  ->  [육아, 휴직, 조건, 알려, 줘]  ->  [12043, 8871, 3312, 991, 402]
                                                              (숫자 ID로 변환)

2) 임베딩
   각 토큰 ID -> 숫자 벡터로 변환. 이제 모델은 숫자만 다룸

3) 트랜스포머 레이어 통과 (수십 겹)
   여기서 "어떤 단어가 어떤 단어와 관련 있는지"를 계산 (어텐션)

4) 다음 토큰 확률 계산
   "육" 0.31, "육아" 0.22, "회사" 0.08 ...

5) 하나 고르기 (temperature 등이 여기서 작용)

6) 고른 토큰을 입력 뒤에 붙이고 2번으로 돌아감
   ... 끝 토큰이 나오거나 max_tokens에 닿을 때까지 반복
```

**중요한 사실:** 답변 100글자를 만들려면 이 과정을 수십~수백 번 반복합니다. 그래서 답이 길수록 느립니다. 그리고 매번 앞의 모든 토큰을 다시 봅니다. 그래서 **대화가 길어질수록 느려지고 메모리를 더 씁니다.** (KV 캐시가 이걸 완화합니다)

## 여기서 나오는 실무적 결론

1. **모델은 "생각"하고 답하는 게 아닙니다.** 그럴듯한 다음 단어를 이어붙일 뿐입니다. 그래서 존재하지 않는 규정 조항 번호도 자신 있게 만들어냅니다. → [[10-용어사전#환각 Hallucination|환각]]

2. **모델은 우리 회사를 모릅니다.** 학습 데이터에 없었으니까요. 사내 문서를 입력에 같이 넣어줘야 합니다. → RAG

3. **모델은 계산기가 아닙니다.** "3287 × 149"도 다음 토큰 예측으로 답하므로 틀릴 수 있습니다. 정확한 계산은 도구를 붙여야 합니다. → 에이전트

4. **답이 길면 느리고 비쌉니다.** 시스템 프롬프트에 "간결하게 답하라"를 넣는 것만으로 응답 속도가 개선됩니다.

5. **같은 질문에 다른 답이 나올 수 있습니다.** 5번 단계에서 무작위로 고르기 때문입니다. temperature를 0으로 두면 대부분 일정해집니다. (하드웨어 특성상 완전히 같지는 않을 수 있습니다)

## Base 모델과 Instruct 모델

모델 이름 뒤에 붙는 꼬리표를 봐야 합니다.

- **Base:** 다음 단어 예측만 배운 날것. 질문하면 답 대신 비슷한 질문을 이어서 씁니다. 우리에게 쓸모없습니다.
- **Instruct / Chat:** "지시를 따르고 대화하도록" 추가 훈련된 것. **우리는 항상 이걸 씁니다.**

모델 받을 때 `Qwen3-32B-Instruct` 처럼 Instruct가 붙었는지 반드시 확인하세요.

## 정리

정리하면, LLM은 다음 토큰을 확률로 고르는 반복 기계이고, 그래서 지어내고, 우리 회사를 모르고, 계산을 못 하고, 길면 느립니다. 이 네 가지 약점을 메우는 게 앞으로 할 일 전부입니다.
