# 트랜스포머와 어텐션

이 문서는 **한 번 읽고 넘어가면 됩니다.** 구현할 일은 없습니다. 다만 "컨텍스트가 길면 왜 메모리를 많이 먹나", "KV 캐시가 뭔가" 같은 질문에 답하려면 개념이 필요합니다.

## 어텐션: 문장 안에서 서로를 쳐다보기

문장을 이해하려면 **어떤 단어가 어떤 단어와 관계있는지**를 알아야 합니다.

> "김 대리가 박 과장에게 보고서를 줬는데, **그가** 반려했다."

여기서 "그가"는 누구일까요? 사람은 문맥상 박 과장이라고 압니다.
어텐션은 이걸 계산으로 합니다. "그가"라는 토큰이 앞의 모든 토큰을 훑어보면서 **각각에 얼마나 주목할지 가중치**를 매깁니다.

```
"그가" 가 바라보는 정도:
  김 대리   0.15
  박 과장   0.61   <- 여기에 주목
  보고서    0.09
  줬는데    0.05
  ...
```

이게 어텐션(attention, 주의 집중)입니다. 이름 그대로입니다.

## 트랜스포머: 어텐션을 겹겹이 쌓은 구조

트랜스포머는 이 어텐션 계산을 **수십 층 쌓은 것**입니다.

- 아래층: 문법 관계 같은 표면적인 것
- 중간층: 의미 관계
- 위층: 추상적인 추론

층을 통과할수록 표현이 정교해지고, 마지막에 "다음 토큰 확률"이 나옵니다.

2017년에 나온 "Attention Is All You Need" 논문이 시작이고, 지금 쓰는 모든 LLM이 이 구조의 변형입니다.

## 실무에 직결되는 두 가지 성질

### 1. 컨텍스트가 길어지면 비용이 제곱으로 늘어난다

어텐션은 **모든 토큰이 모든 토큰을 쳐다보는** 계산입니다.
토큰이 100개면 100 × 100 = 1만 번, 1,000개면 100만 번입니다. 10배 길어지면 계산은 100배가 됩니다.

**그래서:**
- 컨텍스트 윈도우가 큰 모델은 비쌉니다 (요즘은 개선 기법이 많아 완전한 제곱은 아니지만 경향은 같습니다)
- RAG에서 문서를 무작정 많이 넣으면 느려집니다. **적게, 정확하게 넣는 게 핵심**입니다
- "컨텍스트 128K니까 문서 다 넣으면 되잖아요?" 는 실무에서 안 통합니다. 느리고, 비싸고, 중간에 있는 내용을 모델이 잘 놓칩니다 (lost in the middle 현상)

### 2. KV 캐시가 VRAM을 먹는다

토큰을 하나 생성할 때마다 앞의 모든 토큰에 대한 계산을 다시 하면 낭비입니다.
그래서 이미 계산한 값(Key, Value)을 저장해두고 재활용합니다. 이게 **KV 캐시**입니다.

문제는 이게 VRAM을 먹는다는 것입니다. 그리고 **사용자 수 × 대화 길이**에 비례합니다.

```
모델 가중치     : 고정 (예: 20GB)
KV 캐시         : 사용자 수와 대화 길이에 따라 변동 (수 GB ~ 수십 GB)
------------------------------------------------
필요 VRAM       : 둘의 합 + 여유분
```

**GPU 견적 낼 때 KV 캐시를 빼먹으면 실서비스에서 터집니다.** [[42-GPU 사이징]] 에서 계산법을 다룹니다.

## 알아두면 좋은 변형 용어

- **MoE (Mixture of Experts):** 전체 파라미터 중 일부만 골라 쓰는 구조. "총 235B, 활성 22B" 같은 표기가 이겁니다. 성능은 큰 모델급인데 계산은 적게 듭니다. 다만 **VRAM에는 전체가 올라가야** 해서 메모리 요구는 여전히 큽니다.
- **Flash Attention:** 어텐션을 GPU 메모리 효율적으로 계산하는 기법. 켜면 빨라집니다. 대부분 기본 활성화입니다.
- **RoPE / 컨텍스트 확장:** 학습 때보다 긴 입력을 처리하게 늘리는 기법. 늘리면 성능이 조금 떨어질 수 있습니다.

## 정리

정리하면, 트랜스포머는 "모든 토큰이 서로를 쳐다보는" 어텐션을 겹겹이 쌓은 구조이고, 그 대가로 컨텍스트가 길수록 계산과 메모리가 급격히 늘어납니다. 실무 결론은 하나입니다. **컨텍스트에 아무거나 많이 넣지 말고, 필요한 것만 정확히 넣어라.**
