# 내 과제 정의: 폐쇄망 로컬 LLM

## 폐쇄망 로컬 LLM이 뭔가

**로컬 LLM**은 ChatGPT 같은 걸 남의 서버가 아니라 **우리 회사 서버 안에서 직접 돌리는 것**입니다.

비유하자면 이렇습니다. 지금까지는 회사에 정수기가 없어서 직원들이 편의점(OpenAI, Anthropic)에 가서 생수를 사 마셨습니다. 그런데 금융회사는 "직원이 밖에 나가서 뭘 사 오는 것 자체가 위험하다"고 봅니다. 그래서 **회사 안에 자체 정수 설비를 놓는 것**, 그게 로컬 LLM 구축입니다.

**폐쇄망**은 그 설비가 놓일 공간에 **수도관(인터넷)이 아예 안 들어온다**는 뜻입니다. 그래서 설비도, 필터도, 매뉴얼도 전부 미리 트럭에 실어서 반입해야 합니다.

## 이 제약이 만드는 실제 차이

| 일반 환경 | 폐쇄망 |
|---|---|
| `pip install` 하면 끝 | 패키지를 사전에 다 내려받아 반입 |
| 모델을 HuggingFace에서 다운로드 | 모델 파일(수십 GB)을 물리 매체로 반입 |
| API 키 하나로 GPT 호출 | 우리 GPU 서버에서 직접 추론 |
| 모델 업데이트 = 버전 숫자 변경 | 반입 심사 다시 |
| 문제 생기면 구글 검색 | 사내 자료 + 미리 받아둔 문서만 |

**그래서 "무엇을 미리 챙겨 들어가느냐"가 프로젝트의 절반**입니다. 이건 [[40-폐쇄망 반입 체크리스트]] 에서 다룹니다.

## 금융권이라 추가로 붙는 것

1. **망분리 규정.** 내부망 서버에서 외부 통신이 일절 없어야 합니다. 로컬 LLM은 이 요건을 만족하는 유일한 현실적 선택지라서 도입하는 겁니다.
2. **로그와 추적성.** 누가 무엇을 물었고 모델이 뭐라 답했는지 남아야 합니다. 감사(audit) 대응용입니다.
3. **개인정보와 신용정보.** 모델에 넣는 데이터, 모델이 뱉는 답 모두 관리 대상입니다. 특히 학습(파인튜닝)에 실데이터를 쓰면 심의 난이도가 확 올라갑니다.
4. **모델의 답이 틀릴 수 있다는 전제.** 금융 상담이나 규정 안내에 쓰면 오답 하나가 사고입니다. 그래서 대부분 **사람이 최종 확인하는 보조 도구**로 먼저 시작합니다.

자세한 건 [[43-금융권 보안 규제 고려사항]].

## 현실적인 1차 목표를 잡자

처음부터 "사내 전용 GPT"를 만들려 하면 100% 실패합니다. 보통 이 순서로 갑니다.

1. **1단계 (지금 목표):** 사내 문서 질의응답. "취업규칙에서 육아휴직 조건 알려줘" 수준. 오답이 나도 사고가 아닌 영역.
2. **2단계:** 개발자 보조. 사내 코드 규약, 레거시 코드 설명, 테스트 코드 생성.
3. **3단계:** 업무 시스템 연동(에이전트). 모델이 사내 API를 호출해서 실제 조회까지.

이 볼트의 실습은 **1단계를 완주하고 3단계 맛보기**까지 데려다줍니다.

## 성공 기준을 미리 적어두기

- [ ] 인터넷 완전 차단 상태에서 모델이 응답한다
- [ ] 사내 문서 기반으로 답하고, **출처 문서를 같이 표시**한다
- [ ] 동시 사용자 N명에서 응답 지연이 X초 이내다
- [ ] 모든 질의/응답이 로그로 남는다
- [ ] 모델이 모르면 "모른다"고 답한다 (지어내지 않는다)
