## 설치와 실행

### `ollama: command not found`

설치 후 터미널을 새로 열지 않아서 PATH가 반영이 안 된 경우가 대부분입니다. PowerShell을 껐다 켜세요.

### `Connection refused` / `APIConnectionError`

Ollama 서비스가 안 떠 있습니다.

```powershell
ollama list          # 응답이 있으면 살아있음
```

Windows에서는 트레이 아이콘을 확인하거나 Ollama를 다시 실행하세요.

### PowerShell 스크립트 실행 정책 오류

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### `pip install` 이 아주 느리거나 실패

사내망 프록시나 방화벽 문제일 수 있습니다. 사내 미러 저장소가 있는지 확인하세요.

## 모델 관련

### 모델이 안 뜬다 (VRAM 부족)

```
CUDA out of memory
```

순서대로 시도하세요.

1. 더 작은 모델 또는 더 강한 양자화 (`qwen3:8b` → `qwen3:4b`)
2. 컨텍스트 길이 축소 (`--max-model-len 4096`)
3. 동시 처리 수 제한 (`--max-num-seqs 4`)
4. `--gpu-memory-utilization` 을 0.85로 낮춤 (역설적이지만 다른 프로세스와 충돌 시 도움)
5. 다른 GPU 사용 프로세스 종료 (`nvidia-smi` 로 확인)

### 응답이 너무 느리다

| 원인 | 확인 방법 | 대응 |
|---|---|---|
| CPU로 돌고 있음 | `nvidia-smi` 에서 GPU 사용률 0% | GPU 인식 설정 확인 |
| 모델이 VRAM에 다 안 올라감 | 로그에 offload 관련 메시지 | 양자화 강화, 작은 모델 |
| 컨텍스트가 너무 김 | 프롬프트 토큰 수 확인 | RAG에서 k를 줄임 |
| 답변이 너무 김 | 출력 토큰 수 확인 | "간결하게" 프롬프트 + max_tokens |

### 같은 문장을 무한 반복한다

```python
repetition_penalty=1.1   # 또는 frequency_penalty
```

양자화를 너무 강하게(INT3 이하) 했을 때도 발생합니다.

### `<think>` 태그가 답변에 섞여 나온다

추론 모드가 켜진 모델입니다. [[33-실습3 프롬프트와 스트리밍]] 의 `strip_think` 참고.

### 한국어 답변이 어색하거나 영어가 섞인다

1. 시스템 프롬프트에 "반드시 한국어로 답하세요" 명시
2. 한국어 학습 비중이 높은 모델로 교체
3. 모델 크기를 키움 (작은 모델일수록 다국어가 약합니다)

## RAG 관련

### 엉뚱한 문서를 찾아온다

**먼저 검색 결과를 직접 출력해서 확인하세요.** 모델 탓하기 전에 검색부터 봅니다.

```python
for h in retrieve(question, k=10):
    print(f"{h['score']:.3f}  {h['source']}  {h['text'][:80]}")
```

원인별 대응:

| 원인 | 대응 |
|---|---|
| 청크가 너무 큼 | 500~800자로 축소 |
| 청크가 너무 작음 | 800~1200자로 확대, overlap 늘림 |
| 조항 번호로 검색 | 하이브리드 검색 도입 |
| 임베딩 모델이 한국어에 약함 | 다국어 임베딩 모델로 교체 후 **전체 재색인** |
| 문서가 애초에 색인 안 됨 | `collection.count()` 확인 |

### 검색은 잘 되는데 답변이 이상하다

이제 프롬프트 문제입니다.

1. 검색된 청크가 실제로 프롬프트에 들어갔는지 출력해서 확인
2. 시스템 프롬프트에 "제공된 자료만 사용" 강조
3. `temperature` 를 0~0.1로
4. 청크 개수(k)를 줄여봄. **많이 넣는다고 좋아지지 않습니다**

### 모르는 걸 자꾸 지어낸다

1. `min_score` 컷을 올립니다 (0.3 → 0.45)
2. 시스템 프롬프트에 거부 문구를 **정확한 문장으로** 지정합니다
3. few-shot 예시에 "모른다고 답하는 예시"를 넣습니다
4. 그래도 안 되면 모델 크기를 올립니다. **작은 모델은 지시 준수가 약합니다**

### PDF에서 텍스트가 안 나온다

스캔본(이미지 PDF)입니다. OCR이 필요합니다.

```powershell
pip install pytesseract pdf2image
```

Tesseract 본체와 한국어 데이터(`kor.traineddata`)를 별도 설치해야 합니다. **폐쇄망 반입 목록에 추가하세요.**

표가 많은 PDF는 텍스트 순서가 뒤엉킵니다. 이런 문서는 수작업 정리를 각오하세요.

### 벡터 DB를 다시 만들어야 할 때

임베딩 모델을 바꾸면 **반드시 전체 재색인**해야 합니다.

```python
chroma.delete_collection("company_docs")
```

그리고 `build_index.py` 재실행. 문서가 많으면 시간이 오래 걸리니 미리 소량으로 속도를 재보세요.

## 에이전트와 MCP

### 모델이 도구를 안 쓴다

1. 시스템 프롬프트에 "반드시 도구를 사용하라" 강하게 명시
2. 도구 description(docstring)을 더 구체적으로
3. 도구 개수를 10개 이하로 줄임
4. 툴 콜링 지원이 좋은 모델로 교체
5. `temperature=0` 확인

### 도구 인자가 엉뚱하게 들어온다

- 파라미터 description에 **형식과 예시**를 명시 (`"8자리 사번. 예: 20240101"`)
- 도구 안에서 입력 검증 후 명확한 오류 메시지 반환. 모델이 그걸 보고 다시 시도합니다

### MCP 서버가 연결이 안 된다

먼저 단독 실행해서 에러를 확인하세요.

```powershell
python mcp_hr_server.py
```

입력 대기로 멈춰 있으면 정상입니다 (Ctrl+C로 종료). 에러 메시지가 나오면 그걸 고칩니다.

경로 문제도 흔합니다. `StdioServerParameters` 의 args에 **절대 경로**를 쓰면 확실합니다.

### 에이전트가 무한 루프를 돈다

`max_turns` 를 반드시 설정하세요. 그리고 로그를 봐서 어떤 도구를 반복 호출하는지 확인합니다. 대개 그 도구가 유용한 결과를 못 돌려주고 있습니다.

## 폐쇄망 특유의 문제

### 뭔가 실행하면 몇 분씩 멈춰 있다

라이브러리가 인터넷 접속을 시도하고 타임아웃을 기다리는 중입니다.

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

Windows라면:

```powershell
$env:HF_HUB_OFFLINE = "1"
$env:TRANSFORMERS_OFFLINE = "1"
```

### `pip install --no-index` 가 실패한다

```
ERROR: Could not find a version that satisfies the requirement ...
```

wheel 파일이 없거나 플랫폼이 안 맞습니다. `wheels/` 폴더에 해당 패키지 파일이 실제로 있는지, 파일명의 플랫폼 태그가 맞는지 확인하세요. [[40-폐쇄망 반입 체크리스트]]

### 웹 UI가 깨져서 나온다

Gradio, Streamlit 등이 CDN에서 리소스를 받으려다 실패한 겁니다. 오프라인 모드 설정을 찾아보거나, **FastAPI + 정적 HTML로 직접 만드는 게 확실합니다.**

### 무엇을 검색해야 할지 모르겠을 때

폐쇄망에서 막히면 검색이 안 됩니다. 그래서 **반입 전에 문서를 챙기는 게 중요**하다고 반복해서 말한 겁니다.

그래도 막혔다면:
1. 반입한 오프라인 문서를 먼저 뒤진다
2. 에러 메시지를 정확히 적어서 외부망 PC에서 검색한다
3. 라이브러리 소스 코드를 직접 읽는다 (`site-packages` 안에 다 있습니다)

3번을 무시하지 마세요. 폐쇄망에서는 이게 가장 확실한 방법일 때가 많습니다.
