# 수학, 실무에서 쓰는 것만

**결론부터: 수식을 풀 일은 없습니다.** 다만 아래 네 가지는 개념으로 알아야 문서와 에러 메시지가 읽힙니다. 30분이면 됩니다.

## 1. 벡터 = 숫자 목록

`[0.12, -0.44, 0.98, ...]` 처럼 숫자를 쭉 나열한 것입니다. 그게 전부입니다.

AI에서 벡터가 중요한 이유는 **뜻을 좌표로 바꿀 수 있기 때문**입니다.
지도 위의 좌표를 생각해보세요. 서울과 인천은 가깝고, 서울과 부산은 멉니다. 좌표만 봐도 거리를 알 수 있죠.
문장도 똑같이 좌표로 바꿔놓으면 "육아휴직"과 "출산휴가"는 가깝고 "육아휴직"과 "환율"은 멉니다.

**실무에서 만나는 순간:** 임베딩 모델이 "1024차원 벡터를 만든다"고 하면, 숫자 1024개짜리 목록을 만든다는 뜻입니다.

## 2. 차원 (Dimension)

벡터 안의 숫자 개수. 위 예에서 1024가 차원입니다.

차원이 높을수록 의미를 세밀하게 담지만, 저장 용량과 검색 비용이 올라갑니다.
실무 임베딩 모델은 보통 384, 768, 1024, 1536 차원을 씁니다.

**주의할 점 하나:** 벡터 DB에 넣을 때와 검색할 때 **같은 임베딩 모델**을 써야 합니다. 차원이 다르면 아예 에러가 나고, 차원이 같아도 모델이 다르면 검색 결과가 엉망이 됩니다. 이건 실습에서 실제로 겪게 됩니다.

## 3. 코사인 유사도 (Cosine Similarity)

두 벡터가 얼마나 비슷한지 재는 대표적인 방법. **-1에서 1 사이 값**이 나오고, 1에 가까우면 비슷합니다.

거리 대신 **방향**을 봅니다. 화살표 두 개가 같은 쪽을 가리키면 1, 직각이면 0, 반대면 -1입니다.
길이(글의 분량)에 영향을 안 받아서 문장 비교에 적합합니다.

**실무에서 만나는 순간:** 벡터 DB 설정에 `distance: cosine` 같은 항목이 나옵니다. 보통 기본값 그대로 쓰면 됩니다.

## 4. 확률과 분포

LLM은 매 순간 "다음 토큰 후보들의 확률"을 계산합니다. 예를 들어 이런 식입니다.

| 후보 토큰 | 확률 |
|---|---|
| 찌개 | 0.42 |
| 볶음밥 | 0.31 |
| 전 | 0.09 |
| ... | ... |

여기서 무엇을 고를지 조정하는 손잡이가 `temperature`, `top_p`, `top_k` 입니다.
temperature를 낮추면 1등을 거의 항상 고르고(재현성 높음), 높이면 아래 후보도 자주 고릅니다(다양함).

**실무에서 만나는 순간:** "답이 매번 달라져요" → temperature를 0으로. "답이 너무 뻔해요" → 올리기.

## 정리

정리하면, 문장을 숫자 목록(벡터)으로 바꾸고, 그 방향이 얼마나 비슷한지(코사인 유사도) 재서 관련 문서를 찾고, 모델은 다음 토큰을 확률로 골라서 문장을 만든다. 이 네 문장이면 충분합니다.
