# GPU 사이징

**"GPU 몇 장 사면 되나요?"** 에 답하기 위한 문서입니다. 견적서를 쓸 때 그대로 쓸 수 있게 정리했습니다.

## 계산 3단계

### 1단계: 모델 가중치

```
가중치(GB) = 파라미터 수(B) × 비트 수 ÷ 8
```

| 모델 | FP16 | INT8 | INT4 |
|---|---|---|---|
| 8B | 16 GB | 8 GB | 4 GB |
| 14B | 28 GB | 14 GB | 7 GB |
| 32B | 64 GB | 32 GB | 16 GB |
| 70B | 140 GB | 70 GB | 35 GB |

### 2단계: KV 캐시

동시 사용자와 컨텍스트 길이에 비례합니다. **여기를 빼먹는 견적이 정말 많습니다.**

대략적인 어림값 (모델마다 다르므로 실측이 필수):

```
KV 캐시(GB) ≈ 동시 요청 수 × 컨텍스트 토큰 수 × 0.0005 ~ 0.002
```

32B 모델, 8K 컨텍스트, 동시 10명이면 대략 **5~15GB** 정도를 잡습니다.

### 3단계: 여유분

실행 오버헤드, 활성화 메모리, 단편화로 **10~20%** 를 더합니다.

### 합산

```
필요 VRAM = 가중치 + KV 캐시 + 여유분
```

## 실전 예시 3가지

### 사례 A: 소규모 부서 시범 (동시 3~5명)

- 모델: 14B INT4 → 7GB
- KV 캐시 (8K × 5) → 약 3GB
- 여유분 → 2GB
- **합계 약 12GB → RTX 4090(24GB) 또는 L4(24GB) 1장**

### 사례 B: 전사 문서 Q&A (동시 15~20명)

- 모델: 32B AWQ(INT4) → 16GB
- KV 캐시 (8K × 20) → 약 12GB
- 여유분 → 5GB
- **합계 약 33GB → A6000(48GB) 1장 또는 L40S(48GB) 1장**

### 사례 C: 품질 우선 + 여러 서비스 (동시 30명+)

- 모델: 70B INT4 → 35GB
- KV 캐시 (8K × 30) → 약 20GB
- 여유분 → 10GB
- **합계 약 65GB → A100 80GB 1장, 또는 48GB 2장 (텐서 병렬)**

## GPU 선택 참고

| GPU | VRAM | 특징 |
|---|---|---|
| RTX 4090 / 5090 | 24~32GB | 가성비 최고. **다만 데이터센터 라이선스 이슈 확인 필요** |
| L4 | 24GB | 전력 효율 좋음. 저전력 서버 |
| L40S | 48GB | 추론용 주력. 가성비 좋음 |
| A6000 / A6000 Ada | 48GB | 워크스테이션급 |
| A100 | 40 / 80GB | 검증된 선택. 중고 시장 있음 |
| H100 / H200 | 80 / 141GB | 최상급. 비쌈 |

**금융권 조달 시 주의:** RTX 계열(지포스)은 NVIDIA 라이선스상 데이터센터 사용에 제약이 있을 수 있습니다. **구매 전에 반드시 확인하세요.** 감사에서 지적당하면 곤란해집니다.

## 여러 장 쓰기

한 장에 안 들어가면 두 가지 방법이 있습니다.

**텐서 병렬 (Tensor Parallel):** 모델 하나를 여러 GPU에 쪼개 올립니다.

```bash
--tensor-parallel-size 2
```

- 장점: 큰 모델을 돌릴 수 있음
- 단점: GPU 간 통신 오버헤드. NVLink가 있으면 훨씬 유리

**복제 (Replica):** 같은 모델을 여러 장에 각각 올리고 부하를 나눕니다.

- 장점: 처리량이 거의 선형으로 증가. 장애 대응 가능
- 단점: 각 GPU에 모델이 다 들어가야 함

**판단:** 모델이 한 장에 들어가면 복제, 안 들어가면 텐서 병렬입니다.

## 속도 목표 잡기

| 지표 | 목표 | 비고 |
|---|---|---|
| TTFT (첫 글자까지) | 1초 이내 | 스트리밍이면 이게 체감 속도 |
| 생성 속도 | 20 tokens/s 이상 | 사람 읽는 속도와 비슷 |
| 전체 응답 | 5~10초 이내 | RAG 검색 시간 포함 |

**RAG는 LLM 호출 전에 임베딩과 검색 시간이 추가됩니다.** 보통 0.1~0.5초 정도지만, 리랭킹이나 질문 재작성을 넣으면 몇 초가 더 붙습니다. 전체 예산을 짜서 배분하세요.

## 반드시 실측하세요

위 계산은 **견적 초안용**입니다. 실제로는 모델과 설정에 따라 크게 달라집니다.

```bash
# 부하 테스트 도구 예시
pip install locust
```

측정할 것:

1. 동시 1명일 때 응답 시간
2. 동시 5, 10, 20명일 때 응답 시간 변화
3. **어디서 급격히 느려지는지** (이 지점이 실질 수용 한계)
4. `nvidia-smi` 로 VRAM 사용량 추이

**가능하면 GPU를 사기 전에 클라우드에서 같은 사양을 몇 시간 빌려 측정하세요.** 몇만 원으로 수천만 원짜리 결정의 근거를 만들 수 있습니다. (물론 사내 문서를 클라우드에 올리면 안 되니, 성능 측정용 더미 데이터로 하세요)

## 비용을 줄이는 순서

GPU를 더 사기 전에 이것부터 해보세요.

1. **`--max-model-len` 을 줄인다.** 32K를 8K로 줄이면 KV 캐시가 크게 줄어듭니다
2. **양자화 수준을 높인다.** FP16 → INT4
3. **모델 크기를 낮춰본다.** 32B → 14B 로 품질이 얼마나 떨어지는지 골든셋으로 측정. 생각보다 차이가 작을 수 있습니다
4. **동시 처리 상한을 걸고 큐로 받는다.** 대기 몇 초는 대개 허용됩니다
5. **자주 나오는 질문은 캐싱한다.** 같은 질문에 매번 추론할 이유가 없습니다

5번이 의외로 효과가 큽니다. 사내 문서 Q&A는 질문이 상당히 반복됩니다.

## 견적서에 넣을 문장 예시

> 32B급 모델을 INT4 양자화하여 동시 20명을 처리하기 위해 VRAM 48GB 이상이 필요합니다.
> 모델 가중치 16GB, KV 캐시 약 12GB, 실행 오버헤드 5GB를 합산한 값이며,
> 향후 컨텍스트 확장과 사용자 증가를 고려해 48GB 카드 2장(복제 구성)을 권장합니다.
> 1장 구성 시 장애 발생하면 서비스 전면 중단됩니다.

마지막 문장이 예산 승인에 효과적입니다. 이중화는 금융권에서 익숙한 논리니까요.
