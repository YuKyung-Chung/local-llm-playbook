# 평가와 모니터링

**"좋아졌는지 나빠졌는지 모르는 상태로 운영하는 것"** 이 가장 위험합니다. 측정 체계부터 만드세요.

## 1. 골든 데이터셋이 먼저다

모델을 바꾸든, 프롬프트를 고치든, 청크 크기를 바꾸든, **비교 기준이 없으면 개선인지 개악인지 알 수 없습니다.**

### 만드는 법

1. **현업 담당자와 함께** 실제 자주 들어오는 질문을 모읍니다
2. 각 질문의 정답과 근거 문서를 사람이 확정합니다
3. **답이 없어야 하는 질문을 20~30% 섞습니다** (환각 방어 측정용)
4. 최소 30개, 목표 100개

### 구성 비율 권장

| 유형 | 비율 | 목적 |
|---|---|---|
| 문서에 명확히 있는 질문 | 40% | 기본 정확도 |
| 여러 문서를 조합해야 하는 질문 | 20% | 검색 품질 |
| 표현이 다른 질문 (구어체, 오타) | 15% | 실사용 대응 |
| **답이 없는 질문** | 25% | **환각 방어** |

마지막이 핵심입니다. 정확도 95%인데 모르는 걸 다 지어내는 시스템은 금융권에서 쓸 수 없습니다.

## 2. 무엇을 측정하나

### 검색 단계

**답변이 나쁠 때 원인의 70%는 검색입니다.** 여기부터 재세요.

| 지표 | 의미 | 목표 |
|---|---|---|
| Recall@k | 정답 문서가 상위 k개 안에 있는 비율 | 90% 이상 |
| 정답 문서 순위 | 1위에 나오는 비율 | 높을수록 좋음 |
| 검색 실패율 | min_score 미달로 아무것도 못 찾는 비율 | 낮게, 단 무리하지 말 것 |

### 생성 단계

| 지표 | 측정 방법 |
|---|---|
| 정확도 | must_include 키워드 포함 여부 |
| 환각률 | 답 없는 질문에 답을 지어낸 비율. **가장 중요** |
| 출처 표시율 | 출처를 제대로 붙였는지 |
| 형식 준수율 | 지정한 길이와 형식을 지켰는지 |

### 운영 지표

| 지표 | 목표 |
|---|---|
| TTFT | 1초 이내 |
| 전체 응답 시간 (p50 / p95) | 5초 / 15초 이내 |
| 오류율 | 1% 미만 |
| GPU 사용률 | 70~90% (너무 낮으면 과투자) |

**p95를 보세요.** 평균만 보면 소수의 아주 느린 요청을 놓칩니다. 사용자 불만은 거기서 나옵니다.

## 3. 평가 자동화

[[39-실습9 통합 완성본|실습 9]]의 `eval.py` 를 확장합니다. 핵심은 **변경할 때마다 돌리고 기록을 남기는 것**입니다.

```python
import json, datetime
from pathlib import Path

def run_eval(tag: str):
    """tag: 이번 설정을 식별할 이름. 예: 'qwen32b-chunk800-k4'"""
    results = {"tag": tag, "ts": datetime.datetime.now().isoformat(),
               "cases": [], "summary": {}}

    # ... 각 케이스 실행 ...

    total = len(results["cases"])
    correct = sum(1 for c in results["cases"] if c["ok"])
    unanswerable = [c for c in results["cases"] if c["type"] == "unanswerable"]
    hallucinated = sum(1 for c in unanswerable if not c["ok"])

    results["summary"] = {
        "accuracy": correct / total,
        "hallucination_rate": hallucinated / len(unanswerable) if unanswerable else 0,
        "avg_latency_ms": sum(c["latency"] for c in results["cases"]) // total,
    }

    out = Path(f"eval_results/{tag}.json")
    out.parent.mkdir(exist_ok=True)
    out.write_text(json.dumps(results, ensure_ascii=False, indent=2), encoding="utf-8")
    return results["summary"]
```

**설정을 바꿀 때마다 tag를 다르게 해서 돌리고, 결과를 비교하세요.**

```
qwen14b-chunk500-k3  : 정확도 72%, 환각률 18%, 평균 4.2초
qwen14b-chunk800-k4  : 정확도 81%, 환각률 12%, 평균 4.8초
qwen32b-chunk800-k4  : 정확도 88%, 환각률  6%, 평균 9.1초
```

이런 표가 있으면 **"32B로 가야 하는 이유"를 숫자로 설명**할 수 있습니다. 예산 승인에 이만한 근거가 없습니다.

## 4. LLM으로 채점하기

키워드 매칭만으로는 한계가 있습니다. 표현이 달라도 맞는 답일 수 있으니까요.

```python
JUDGE_PROMPT = """다음 답변이 정답과 사실적으로 일치하는지 판단하세요.
표현이 달라도 내용이 맞으면 일치로 봅니다.
"일치" 또는 "불일치" 한 단어로만 답하세요.

[질문] {question}
[기준 정답] {reference}
[평가할 답변] {answer}"""


def judge(question, reference, answer) -> bool:
    resp = llm.chat.completions.create(
        model=CHAT_MODEL,
        messages=[{"role": "user", "content": JUDGE_PROMPT.format(
            question=question, reference=reference, answer=answer)}],
        temperature=0, max_tokens=10,
    )
    return "일치" in resp.choices[0].message.content
```

**주의:** 채점 모델도 틀립니다. 같은 모델로 자기 답을 채점하면 후하게 줍니다.
**최종 판단은 사람이 하되, 100건을 다 볼 수 없을 때 1차 선별용으로** 쓰세요.

## 5. 운영 중 모니터링

### 로그에서 뽑을 것

[[35-실습5 RAG 챗봇 만들기|실습 5]]에서 남긴 `qa.jsonl` 을 주기적으로 분석합니다.

```python
import json
from collections import Counter
from pathlib import Path

records = [json.loads(l) for l in Path("logs/qa.jsonl").read_text(encoding="utf-8").splitlines()]

# 검색 실패한 질문들 = 문서 보강 목록
failed = [r["question"] for r in records if r["top_score"] is None or r["top_score"] < 0.35]
print("검색 실패 질문 TOP 20:")
for q, cnt in Counter(failed).most_common(20):
    print(f"  {cnt}회  {q}")

# 자주 나오는 질문 = 캐싱 후보, FAQ 후보
print("\n빈출 질문:")
for q, cnt in Counter(r["question"] for r in records).most_common(10):
    print(f"  {cnt}회  {q}")

# 느린 요청
slow = sorted(records, key=lambda r: -r["latency_ms"])[:10]
print("\n가장 느린 요청:")
for r in slow:
    print(f"  {r['latency_ms']}ms  {r['question'][:40]}")
```

**검색 실패 질문 목록이 가장 값진 자산입니다.** 사용자가 알고 싶어 하는데 우리 문서에 없는 것들이니까요. 이걸 현업에 전달하면 문서 보강이 이루어집니다.

## 7. 배포 전 체크리스트

새 모델이나 설정을 운영에 올리기 전에.

- [ ] 골든셋 정확도가 기존 대비 하락하지 않았는가
- [ ] **환각률이 올라가지 않았는가** (정확도보다 우선)
- [ ] p95 응답 시간이 목표 내인가
- [ ] 권한 필터가 정상 동작하는가
- [ ] 출처 표시가 정확한가
- [ ] 롤백 절차가 준비돼 있는가

**환각률은 정확도보다 우선하는 지표입니다.** 정확도가 3% 올라도 환각률이 5% 올랐다면 배포하지 마세요. 금융권에서 잘못된 답 하나가 만드는 손실이 맞는 답 여러 개의 편익보다 큽니다.

## 정리

정리하면, 골든셋을 먼저 만들고, 바꿀 때마다 측정하고, 검색 실패 로그를 개선 재료로 쓰는 것. 이 세 가지가 운영의 전부입니다. 그리고 환각률은 항상 정확도보다 우선입니다.
