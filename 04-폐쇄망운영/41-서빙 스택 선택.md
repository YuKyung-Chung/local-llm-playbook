# 서빙 스택 선택

"무엇으로 모델을 띄울 것인가"를 정하는 문서입니다.

## 세 가지 선택지

| | Ollama | vLLM | llama.cpp |
|---|---|---|---|
| 설치 난이도 | **아주 쉬움** | 중간~어려움 | 중간 |
| OS | Win/Mac/Linux | 사실상 Linux | 전부 |
| GPU 필수 | 아니오 | **예** | 아니오 |
| 동시 처리 성능 | 낮음 | **매우 높음** | 낮음 |
| 모델 포맷 | GGUF | safetensors, AWQ, GPTQ | GGUF |
| OpenAI 호환 API | 예 | 예 | 예 (server 모드) |
| 적합한 용도 | 학습, PoC, 개인용 | **사내 공용 서비스** | CPU 환경, 엣지 |

## 판단 기준

```
GPU가 있는가?
  아니오 -> llama.cpp 또는 Ollama (CPU 모드). 작은 모델만.
  예
   |
동시 사용자가 몇 명인가?
  5명 이하 -> Ollama로도 가능
  10명 이상 -> vLLM
```

**대부분의 사내 프로젝트는 결국 vLLM으로 갑니다.** 동시 처리 성능 차이가 크기 때문입니다.

## vLLM이 왜 빠른가

핵심은 두 가지입니다.

**1. 연속 배칭 (Continuous Batching)**

Ollama는 요청을 대체로 순서대로 처리합니다. 5명이 동시에 물으면 뒷사람은 앞사람이 끝날 때까지 기다립니다.

vLLM은 **여러 요청을 GPU에 한 번에 태웁니다.** 게다가 한 요청이 끝나면 빈 자리에 대기 중인 요청을 즉시 채워 넣습니다. 버스가 정류장마다 서서 사람을 태우는 것과 비슷합니다.

**2. PagedAttention**

[[22-트랜스포머와 어텐션|KV 캐시]] 메모리를 운영체제의 페이징처럼 잘게 나눠 관리합니다. 메모리 낭비가 줄어서 **같은 GPU로 더 많은 동시 요청**을 받을 수 있습니다.

결과적으로 동시 사용자가 많을수록 격차가 벌어집니다. 10명 이상이면 몇 배 차이가 납니다.

## vLLM 기본 실행

```bash
python -m vllm.entrypoints.openai.api_server \
  --model /models/Qwen3-32B-Instruct-AWQ \
  --served-model-name qwen3-32b \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.90 \
  --quantization awq
```

주요 옵션:

| 옵션 | 의미 | 튜닝 포인트 |
|---|---|---|
| `--max-model-len` | 최대 컨텍스트 길이 | **필요한 만큼만.** 크면 KV 캐시가 메모리를 먹음 |
| `--gpu-memory-utilization` | GPU 메모리 사용 비율 | 0.85~0.95. 너무 높이면 OOM |
| `--tensor-parallel-size` | GPU 여러 장에 모델 분할 | GPU 개수만큼 |
| `--max-num-seqs` | 동시 처리 요청 수 상한 | 메모리 부족 시 낮춤 |
| `--quantization` | 양자화 방식 | awq, gptq, fp8 등 |
| `--api-key` | API 키 인증 | **사내 운영에서는 반드시 설정** |

호출은 실습과 똑같습니다. base_url만 바뀝니다.

```python
client = OpenAI(base_url="http://llm.company.local:8000/v1", api_key="사내키")
```

**이게 실습을 Ollama로 시작한 이유입니다.** 코드를 안 바꿔도 됩니다.

## 실전 권장 경로

```
1단계: 개발 PC + Ollama
        -> 개념 학습, 프로토타입
2단계: 사내 GPU 서버 + Ollama
        -> 소수 인원 시범 운영, 실제 문서로 품질 검증
3단계: 사내 GPU 서버 + vLLM
        -> 전사 오픈
```

2단계를 건너뛰지 마세요. **vLLM 세팅에서 막혀서 프로젝트 전체가 지연되는 경우가 많습니다.** Ollama로 먼저 "우리 문서로 답이 제대로 나오는가"를 확인하고, 그다음에 성능 문제를 푸는 게 순서입니다.

## 컨테이너로 운영하기

폐쇄망에서는 이미지를 파일로 옮깁니다.

```bash
# 인터넷 환경에서
docker pull vllm/vllm-openai:v0.X.X
docker save vllm/vllm-openai:v0.X.X -o vllm.tar

# 폐쇄망에서
docker load -i vllm.tar
```

```bash
docker run --gpus all \
  -v /models:/models \
  -p 8000:8000 \
  vllm/vllm-openai:v0.X.X \
  --model /models/Qwen3-32B-Instruct-AWQ \
  --max-model-len 8192
```

GPU를 쓰려면 호스트에 **NVIDIA Container Toolkit**이 설치돼 있어야 합니다. 이것도 반입 목록에 넣으세요.

## 고가용성 구성

전사 서비스가 되면 필요합니다.

```
              [로드밸런서]
                /      \
      [vLLM #1]        [vLLM #2]
       GPU 서버1         GPU 서버2
```

- `/health` 엔드포인트로 헬스체크
- 한 대가 죽어도 서비스 유지
- 모델 업데이트 시 무중단 롤링 배포 가능

다만 **1단계부터 이걸 하려 하지 마세요.** 단일 서버로 시작해서 실제 부하를 본 뒤 결정하는 게 맞습니다.

## 선택 요약

- **지금 학습 중이라면** Ollama
- **사내 시범 운영이라면** Ollama (GPU 서버에)
- **전사 오픈이라면** vLLM
- **GPU 예산이 없다면** llama.cpp + 작은 모델로 범위를 좁힌 서비스

## 정리

정리하면, 개발은 Ollama로 편하게 하고 운영은 vLLM으로 가되, API 규격이 같으니 코드는 그대로 쓸 수 있습니다. 서두르지 말고 단계를 밟으세요.
