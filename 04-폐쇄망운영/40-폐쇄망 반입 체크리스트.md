# 폐쇄망 반입 체크리스트

**이 프로젝트에서 가장 많은 사고가 나는 지점입니다.** 뭔가 하나 빠뜨리면 다시 반입 절차를 밟아야 하고, 그게 며칠에서 몇 주입니다.

## 원칙: 반입은 한 번에 끝낸다는 생각을 버려라

현실적으로 2~3회는 추가 반입이 필요합니다. 그러니 **1차 반입에 "혹시 필요할지도"를 최대한 넣으세요.** 용량은 싸고 시간은 비쌉니다.

---

## 1. 모델 파일

- [ ] **생성 모델** (예: Qwen3-32B-Instruct)
- [ ] **임베딩 모델** (예: bge-m3) ← **가장 많이 빠뜨립니다**
- [ ] 리랭커 모델 (선택이지만 넣어두면 좋음)
- [ ] **백업용 작은 모델** (예: 8B) ← GPU 문제 생겼을 때 생명줄
- [ ] 모델 라이선스 파일 원문
- [ ] 모델 카드 (성능, 학습 데이터, 제한사항 설명 문서). **심의 자료로 필요합니다**

### 포맷 확인

운영 스택에 따라 필요한 포맷이 다릅니다. **미리 확정하거나 둘 다 가져가세요.**

| 스택 | 필요 포맷 |
|---|---|
| Ollama / llama.cpp | GGUF |
| vLLM | safetensors (원본 또는 AWQ/GPTQ 양자화) |

### 체크섬 기록

```powershell
Get-FileHash model.gguf -Algorithm SHA256
```

반입 전후로 대조하세요. 대용량 파일은 전송 중 깨지는 일이 실제로 있습니다.

---

## 2. 런타임과 시스템

- [ ] Python 설치 파일 (**대상 서버 OS에 맞는 것**)
- [ ] Ollama 또는 vLLM 설치 파일
- [ ] CUDA 툴킷
- [ ] NVIDIA 드라이버
- [ ] cuDNN (필요 시)
- [ ] Docker 이미지 (컨테이너로 운영한다면 `docker save` 로 tar 저장)

### 버전 조합 미리 검증

**CUDA, 드라이버, PyTorch, vLLM 버전 조합이 안 맞으면 아예 안 뜹니다.** 폐쇄망 안에서 이걸 맞추려고 버전을 바꿔가며 시도하는 건 지옥입니다.

**반드시 반입 전에 개발 환경에서 동일 조합으로 구동 검증을 마치세요.** 그리고 검증한 버전 번호를 문서로 남기세요.

```
검증 완료 조합 (2026-XX-XX)
- OS: Ubuntu 22.04
- NVIDIA Driver: 5XX.XX
- CUDA: 12.X
- Python: 3.11.X
- PyTorch: 2.X.X
- vLLM: 0.X.X
```

## 3. Python 패키지

- [ ] `requirements.txt` (버전 고정)
- [ ] wheel 파일 전체

```powershell
pip freeze > requirements.txt
pip download -r requirements.txt -d wheels
```

### 플랫폼 불일치 함정

**개발 PC가 Windows이고 서버가 Linux면 받은 wheel이 안 맞습니다.**

대상 환경용으로 받으려면:

```powershell
pip download -r requirements.txt -d wheels --platform manylinux2014_x86_64 --python-version 3.11 --only-binary=:all:
```

이 방법도 소스 배포만 있는 패키지에서는 실패합니다. **가장 확실한 건 대상 환경과 같은 OS(리눅스 VM이나 컨테이너)에서 받는 것**입니다.

### 설치 리허설

폐쇄망에 넣기 전에, **인터넷을 끊은 깨끗한 환경에서** 오프라인 설치가 되는지 반드시 시험하세요.

```powershell
pip install --no-index --find-links=wheels -r requirements.txt
```

## 반입 후 첫날 순서

1. 파일 무결성 확인 (체크섬 대조)
2. GPU 인식 확인 (`nvidia-smi`)
3. Python + 패키지 오프라인 설치
4. **모델 로딩만** 먼저 시도 (추론 전에 뜨는지부터)
5. 간단한 추론 1회
6. 임베딩 1회
7. 색인 생성
8. 전체 파이프라인
9. 평가 스크립트 실행

**한 번에 다 하려 하지 말고 단계별로 확인하세요.** 어디서 막혔는지 알아야 대응할 수 있고, 폐쇄망에서는 디버깅 자료가 부족하니 문제 범위를 좁히는 게 훨씬 중요합니다.

## 자주 겪는 사고 모음

| 증상 | 원인 | 예방 |
|---|---|---|
| 임베딩이 안 됨 | 임베딩 모델을 안 가져옴 | 목록에 명시 |
| pip 설치 실패 | 플랫폼 불일치 wheel | 대상 OS에서 download |
| 모델이 안 뜸 | CUDA/드라이버 버전 불일치 | 사전 조합 검증 |
| 라이브러리가 인터넷 접속 시도 | 토크나이저나 설정 파일을 원격에서 받으려 함 | 오프라인 환경변수 설정, 로컬 경로 지정 |
| Gradio/Streamlit UI 깨짐 | CDN에서 리소스 로드 시도 | 오프라인 모드 또는 자체 UI |
| 색인 생성이 며칠 걸림 | 문서량 대비 임베딩 처리량 부족 | 사전에 소량으로 속도 측정 후 산정 |

### 오프라인 환경변수

HuggingFace 라이브러리를 쓴다면 이걸 설정해두세요. 인터넷 접속 시도 자체를 막습니다.

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

이걸 안 걸어두면 **접속 시도 후 타임아웃까지 몇 분씩 멈춰 있습니다.** 원인 파악이 어려운 대표적인 증상입니다.
